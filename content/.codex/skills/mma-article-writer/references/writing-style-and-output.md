# Writing Style And Output

이 문서는 문체, 전술 서술 방식, 금지 표현, 출력 품질 기준을 다룬다.

## Human Writing

가장 중요하다.

AI 특유의 아래 패턴을 제거한다:

- 억지 서사
- 과장된 감탄
- 교과서식 연결
- 뻔한 문장 구조

## 절대 금지 표현

아래 표현은 사용 금지:

- "안녕하세요"
- "오늘 알아볼"
- "~에 대해 알아보겠습니다"
- "최근 MMA 시장에서는"
- "눈여겨볼 필요가 있다"
- "흥미로운 부분이다"
- "팬들의 기대를 모으고 있다"
- "인상적인 모습을 보여줬다"

## 문체 규칙

### 시작 방식

서론 없이 바로 핵심으로 시작한다.

좋은 예:

- "토푸리아는 생각보다 레슬링 압박이 훨씬 거친 선수다."
- "문제는 페레이라의 왼훅이 아니라 케이지 압박이다."
- "사람들이 자꾸 간과하는데, 이 선수는 3라운드부터 움직임이 급격히 죽는다."

나쁜 예:

- "오늘은 UFC 스타 선수인..."
- "최근 큰 관심을 받고 있는..."

### 글 스타일

- 짧은 문장 위주
- 필요할 때만 길게 설명
- 커뮤니티 헤비 유저 느낌
- 지나친 욕설 금지
- 억지 밈 사용 금지
- 전문가인 척하는 현학적 문체 금지
- 단정적으로 쓰되 근거 없이 확신하지 말 것

## 반드시 포함할 요소

가능하면 아래 요소를 포함한다:

- 기술적 버릇
- 경기 흐름 변화 포인트
- 체력 저하 타이밍
- 압박 패턴
- 케이지 사용 습관
- 카운터 습관
- 감량 영향
- 최근 경기력 변화
- 스타일 상성

## 전술 분석 규칙

단순히 아래 수준으로 끝내지 마라:

- "타격이 좋다"
- "레슬링이 강하다"

좋은 예:

> 오말리는 뒤로 빠지면서 원투를 던지는 비율이 높다. 문제는 케이지를 등졌을 때 로우킥 체크 반응이 급격히 느려진다는 점이다.

## Formatting

최종 결과는 Markdown 형식으로 출력한다.

### 구조

- `##`: 메인 섹션
- `###`: 세부 분석
- `Table`: 전적, 스탯 비교
- `>`: 핵심 전술 분석
- 리스트는 최소화

## Image Placement

이미지는 선택 사항이지만, 유의미하면 2~3개까지 넣을 수 있다.

- 가장 안전한 기본값은 생성 이미지다
- 그다음은 사용자가 보유한 로컬 이미지다
- 웹 검색 이미지는 저작권, 라이선스, 출처 확인이 되는 경우에만 사용한다
- 가능하면 이미지를 포스트 폴더 안에 저장하고 `![설명](./image-name.jpg)` 로 연결한다
- 본문 흐름을 끊지 않게 아래 위치를 우선 고려한다:
- 도입부 직후
- 가장 중요한 전술 분석 섹션 직전 또는 직후
- 결론 직전 분위기 전환 지점
- 생성 이미지나 일러스트를 만들었다면, 이 프로젝트에서는 실제 포스트 폴더로 복사 또는 저장하고 `index.md` 에 연결해 블로그에 바로 보이게 만든다

이미지는 문장을 대신하면 안 된다. 이미지 없이도 글은 완결되어야 한다.

## Section Length And Density

섹션이 너무 짧게 끝나면 칼럼의 밀도가 떨어진다.

- 각 `##` 섹션은 기본적으로 2개 이상 문단을 확보한다
- 각 `###` 소제목은 주장만 던지지 말고, 이유와 사례까지 붙인다
- 전술 포인트를 말했으면 경기 장면, 습관, 상성 중 최소 하나로 이어서 설명한다
- 결론 섹션도 요약만 하지 말고, 다음 경기나 향후 시나리오까지 구체화한다
- 전체 분량은 보통 4000~6000자 이상을 기본 목표로 본다

짧은 섹션을 늘릴 때는 미사여구를 추가하지 말고 아래로 확장한다:

- 왜 그런지
- 누구를 상대로 그 패턴이 나왔는지
- 상위 랭커 상대로도 통할지
- 체력, 압박, 케이지, 카운터 리듬에 어떤 영향을 주는지

## Output Rules

출력은 아래 둘 중 하나다:

- 채팅창 Markdown 출력
- 프로젝트에 저장 가능한 `index.md` 형태

## Quality Rules

최종 결과는 반드시 아래 조건을 만족해야 한다:

- AI 냄새 제거
- 실제 MMA 팬 느낌
- 기술 디테일 존재
- 읽는 흐름 자연스러움
- 쓸데없는 미사여구 제거
- 팩트와 의견 분리
- 검색 데이터 기반 작성
- 블로그 반영 요청이 있으면 글과 이미지가 실제 파일 상태까지 완료됨
